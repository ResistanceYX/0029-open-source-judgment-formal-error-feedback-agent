# 能力边界与拒答条件

本项目是 #0029 节点（开源裁判文书形式异常检测反馈 Agent）的开源实现。
以下内容同时是产品边界、提示词边界与代码边界；规则实现不得越过这些边界。

## 一、输出边界：只输出"待核线索"

每条输出必须同时携带：文书指纹、规则来源（规则 ID）、页/段/字符位置、
最小必要原文、触发原因、计算或比对过程（如适用）、备选解释、置信度、复核状态。

本工具**不做**以下任何一件事：

1. 不认定"错判""误判"或裁判结论错误——文本异常不等于实质错判；
2. 不判断法条引注的效力版本、时效与适用正确性——引注解析只到结构化提取与格式检查；
3. 不对事实认定、证据采信、法律适用发表意见；
4. 不生成"没有告警=没有错误"的安全感——报告必须保留无告警免责声明；
5. 不做事实主张——任何概率只能对应规则触发记录，不允许凭常识或模型推断补原文。

## 二、输入边界：只处理合法输入

- 只处理用户主动提供、并声明有权检查的材料（TXT/Markdown）；
- 不抓取、不镜像、不绕过任何平台的验证码、反爬、访问控制或风控；
- 不保存或复用他人 Cookie、token、登录态；
- 登记来源、取得方式、授权、取得时间、文件指纹、正式文本核验状态与允许用途（见 `input_registry.py`）。

## 三、反馈边界：只生成草稿

- 反馈功能只把**人工接受**的线索映射为草稿，附官方渠道指引；
- 默认不自动提交、不批量留言、不使用他人账号；
- 草稿措辞为中性补正请求，不出现"错判/改判/违法"等定性词；
- 对事实认定、证据采信、裁判结论的异议提示走上诉、再审等法定程序。

## 四、拒答条件（实现层硬约束）

| 场景 | 行为 |
|---|---|
| 用户要求批量抓取裁判文书网 | 拒绝，并指向官方下载与授权途径 |
| 用户要求自动提交反馈/留言 | 拒绝，只提供草稿生成 |
| 用户要求判断"这个判决判错了没有" | 拒绝，说明本项目只检查形式异常线索 |
| 输入材料无授权声明 | 拒绝登记之外的任何处理 |

## 五、上游与模型边界

- 不合并、不复制三个上游仓库代码（见 UPSTREAM.md）；
- 当前版本不含任何 LLM 调用；模型辅助检查即使后续加入也**默认关闭**，
  只能作为规则结果的解释层或人工复核辅助，不能产生额外"线索"。
